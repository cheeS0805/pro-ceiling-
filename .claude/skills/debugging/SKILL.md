# Дебаг: спершу причина, потім виправлення

Головне правило: **не вгадувати**. Не міняй код «а раптом допоможе». Спершу доведи, ЩО саме і ЧОМУ зламано, — тоді виправлення буде одне й точне.

## 1. Відтворити

Добийся, щоб баг повторювався стабільно, і запиши, як саме.

| Що зламано | Чим відтворити |
|---|---|
| вигляд / верстка | `npm run verify` → скриншоти в `%TEMP%\pro-ceiling-verify\`; для ширини 375px — сайт в iframe потрібної ширини (headless Chrome не вміє вікно вужче ~500px) |
| кліки, анімації, «відчуття» | Claude in Chrome (`@browser`) — справжній браузер, справжні кліки |
| JS-помилка | консоль: `read_console_messages` у Chrome або ❌ «Консоль без помилок» у `verify` |
| збірка | `npm run build:css` / `build:ts` — читай перший рядок помилки й номер рядка |
| хук | подай хуку JSON вручну **з файлу** (не з командного рядка bash — він їсть `\\` і лапки): `node .claude/hooks/<хук>.mjs < test.json` |

Не вдалося відтворити — не виправляй. Спитай користувачку: що саме вона робила, на якому пристрої, скриншот.

## 2. Ізолювати

Звузь пошук, поки не лишиться одне місце.
- Порівняй «працює» і «не працює»: що між ними різне (ширина екрана, файл, браузер, режим)?
- `git log` / `git diff` — з якого коміту почалось? `git stash` або тимчасовий відкат допоможе перевірити.
- Виміряй, а не дивись на око: `getBoundingClientRect()`, `scrollWidth` проти `clientWidth`, розмір файлу, код виходу.

## 3. Знайти справжню причину

Запитай «чому?» кілька разів, доки не дійдеш до коренів. Пастки, на які ми вже наступали в цьому проєкті:

| Симптом | Справжня причина |
|---|---|
| чорна смуга праворуч на телефоні | `aspect-ratio` + `min-height` розтягують блок ширше за екран → `max-width: 100%` |
| заголовок секції ховається після кліку в меню | «липка» шапка → `scroll-padding-top` (токени `$header-h-*`) |
| хук «нічого не робить», вивід порожній | на Windows `process.exit()` губить асинхронний stdout → `writeSync(1, …)` |
| хук не знаходить рядок, який точно є у файлі | файл з `\r\n`, а шукаємо `\n` → нормалізувати переноси |
| перевірка завжди ✅, навіть коли зламано | тест нічого не ловить (формат логів Chrome інший) → **зворотний тест** |
| Python «не запускається» | `python` — заглушка Microsoft Store → `py` |

Знайшов причину — скажи її користувачці простими словами **до** виправлення.

## 4. Виправити

- Мінімальна правка саме в причині, не в симптомі. Стилі — у `src/scss/` (кольори й розміри — токени), логіка — у `src/script.ts`; згенеровані `styles.css`/`script.js` не чіпай.
- Хуки працюють і тут: якщо PostToolUse повернув ❌ — це підказка, а не перешкода.
- Біля неочевидного виправлення — короткий коментар «чому так», щоб наступна людина не «спростила» назад.

## 5. Довести, що полагоджено

- Повтори **той самий** спосіб відтворення з кроку 1 — і покажи цифри «до → після» (наприклад, «заголовок 79px під шапкою 110px → 225px»).
- `npm run verify` — усе ще ✅?
- Якщо баг міг би повернутися — додай перевірку в `verify.mjs` / `probe.html`, і зроби **зворотний тест**: тимчасово поверни баг і переконайся, що перевірка його ловить.
- Новий тип пастки — допиши рядок у таблицю кроку 3 цього skill і, якщо треба, у «Відомі пастки» в `CLAUDE.md`.
- Запропонуй коміт з поясненням причини (не лише «виправлено»), і спитай перед комітом.
